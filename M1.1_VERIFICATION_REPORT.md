# M1.1 — MEDIA FOUNDATION HARDENING VERIFICATION REPORT

The media foundation layer has been strictly hardened according to the M1.1 specifications. It is fully decoupled from AI and editorial rules, acting solely as a robust deterministic media engine.

## 1. Proxy Scaling — Downscale Only
The proxy generator no longer blindly forces `1280x720`. Instead, it uses `scale=-2:'min(config.max_height,ih)'`. 
- Sources taller than 720p (e.g., 1080p) are securely downscaled while preserving aspect ratios.
- Sources smaller than 720p (e.g., 360p) are preserved at their native resolution without upscaling.
- Verified successfully via `test_1080p.mp4` and `test_360p.mp4` through the E2E script.

## 2. Robust Caching & Signature Validation
The system no longer relies on simple file existence for cache hits. 
- Signatures comprehensively hash the source's content fingerprint (multi-point sampling + size) combined with the explicit generator configurations (`ProxyConfig`, `AudioConfig`) and the tool version (`generator_version`).
- `validate_proxy` and `validate_audio` explicitly perform post-generation FFprobe verification to ensure the generated file matches expected dimensions, duration tolerances, and actually contains media streams.
- If a signature matches but the artifact is missing or corrupted, the system detects it, purges the stale artifact, and regenerates automatically.

## 3. Database Idempotency & Provenance
Re-running a job against an already-processed file no longer blindly duplicates database entries.
- The `MediaAsset` table tracks explicit provenance: `parent_asset_id`, `derivation_signature`, `producer`, and `producer_version`.
- Worker tasks explicitly check the database for assets matching the `parent_asset_id` + `derivation_signature`. 
- If a valid asset exists in the DB and passes FFprobe disk validation, generation is skipped and the existing entity is reused.

## 4. Crash Recovery
A crash recovery script (`scripts/recover_jobs.py`) has been added. 
- It sweeps the database for jobs stuck in the `running` status and safely reverts them to `interrupted`.
- This ensures that if the Celery worker crashes, state can be remediated for retry logic.

## 5. End-to-End Test Suite 
- Added dynamic multi-resolution files (`test_1080p.mp4` and `test_360p.mp4`) to the synthetic video generator.
- Ran the `scripts/process_media.py` harness simulating multiple overlapping runs (Idempotency check).
- Implemented unit tests in `test_media_cache.py` to assert correct cache behavior.
